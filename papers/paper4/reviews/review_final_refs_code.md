## Methods vs code

### What matches (verified line by line)
- **Partitions.** IID uses `array_split` of a permutation. The Dirichlet split draws per-class Dirichlet(α) proportions; α ∈ {1.0, 0.5, 0.1}; N = 4, with 2, 8 and 16 in the scaling study. The TON-IoT host partition assigns each destination IP whole to the currently smallest of four clients, in a fresh random host order per repetition (`randomized=True`, natr runs). A site's own test traffic is the test traffic to its hosts; hosts seen only in test belong to no client. N-BaIoT uses one client per device (N = 9). The references with IID and α = 0.5/0.1 at N = 9 run on the same data. The partition is drawn with prng = 1000 + rep, which is identical for the federated and local-only runs, so pairing per site is valid.
- **Model.** Two Conv1D blocks (32 and 64 filters, kernel 3, max-pool 2) with GroupNorm (8 groups), global average pooling, Dense 128 and 64 with dropout 0.3, and a softmax output. For 25 features and 10 classes this gives 23,754 parameters = 95,016 B. This matches the text.
- **Training.** 50 rounds × 2 local epochs, batch 256, size-weighted averaging. Adam is reset every round (`reset_optimizer`). The centralised model is the same model with the same learning rate, run for 50 × 2 = 100 epochs; its Adam state is kept (stated in S1C). Local-only models are trained on each client's indices alone and selected on the pooled validation set (S1C). The last partial batch is dropped (S1C).
- **Round selection.** The selected round is the earliest maximum of validation macro-F1 (`select`). Test-set scores are logged but never used for a choice. The BN federated re-estimation runs are selected on `val_f1_fedrecal` in compute_values (line 321), as the text says.
- **FedProx.** (μ/2)‖w − w_g‖² over the trainable variables, anchored at the global weights.
- **FedAdam.** m = 0.9m + 0.1Δ and v = 0.99v + 0.01Δ², then w = w + η·m/(√v + 10⁻³), applied to trainable weights only and without bias correction (as in Reddi et al.). The server learning rate used is 0.03 on all three datasets.
- **SCAFFOLD.** Local SGD with the correction g − c_i + c. Option II: c_i⁺ = c_i − c + (x − y_i)/(Kη), with K the actual number of local steps. c += mean(Δc_i). Communication is counted twice. See M5 for the aggregation weights.
- **FedLC.** Calibrated logits log softmax − τ·n_{k,c}^{−1/4}, with the count set to 1 for missing classes. Evaluation uses the uncalibrated output.
- **DP-SGD.** Per-example gradients (`vectorized_map`) are clipped by global L2 norm to C. Noise N(0, (σC)²) is added to the sum, the sum is divided by the expected batch size B, and Adam takes the step. Sampling is Poisson with q = B/n_k and ⌈1/q⌉ draws per epoch; empty draws are skipped but still counted (S1E). The accountant is `dp_accounting` RDP with PoissonSampled(Gaussian(σ)) composed over rounds × epochs × ⌈1/q⌉ steps, δ = 10⁻⁵, reporting the maximum ε over clients. DP runs use GroupNorm and no dropout. Sanity runs: `dp_noclip_nonoise` (C = 0, σ = 0) and `dp_clip_nonoise`. The full-budget runs are `dp_full_sigma1.8` (50 × 2) and `dp_full_nonoise`. The short-schedule non-private reference is `fedavg_gn_short` (GroupNorm with dropout), not the BatchNorm `fedavg_short`.
- **Tuning.** Grids and selected values in S1D match the stage-a/b/lc grid definitions in run_fl_v2.py (`TUNE3_A`, `TUNE3_B`, `TUNE3_LC`, `NB_GRIDS`) and tuned_v3.json for all three datasets: TON 0.003 / 10⁻⁵ / 0.03 / 3 / 0.1 / 0.3; UNSW 0.003 / 10⁻³ / 0.03 / 10 / 0.03 / 0.03; N-BaIoT 10⁻³ / 10⁻⁴ / 0.03 / 1 / 0.1 / 0.1. Stage-b and lc runs used the tuned client learning rate (cfg lr = 0.003 on TON/UNSW and 0.001 on N-BaIoT). Tuning seeds are 100–102 on TON/UNSW (three repetitions) and 100–101 on N-BaIoT (two). Only TON FedProx μ is flagged `_edge`. The centralised learning-rate check uses `tunec_central_*` with seeds 100–102.
- **Reported runs.** Every reported run's stored cfg carries the tuned value: fedprox μ, fedadam server_lr, fedlc τ, scaffold and fedavgsgd lr, and the Adam lr of central, local and FedAvg.
- **Repetitions.** The core, no-port, host-partition, N-BaIoT, BN-re-estimation and personalisation runs have seeds 0–4. Scaling, BN with server-averaged statistics, the 100-round check, short and full DP each have 0–2. DP tuning has 0–1. All counts are as stated.
- **Metrics.** Common-test macro-F1 is computed over all classes. Own-traffic macro-F1 is computed over the classes present in that traffic. Benign FPR and attack detection follow the definitions in the text. Communication is 4 × 95.0 kB × 2 = 0.76 MB per round and 38.0 MB for 50 rounds. The BN re-estimation exchanges (32 + 64) × 2 = 192 values.
- **Statistics.** t-based 95% CIs (ddof 1); paired t-tests over repetitions; Welch tests for comparisons between partitions; Holm step-down correction within each dataset over the PRIMARY lists, which have 19, 13 and 9 entries. "10 of 17" is correct: 3 of 7 on TON, 2 of 5 on UNSW and 5 of 5 on N-BaIoT. The skew trend is the per-repetition polyfit slope over four levels followed by a one-sample t-test. The own-traffic tests use the repetition as the unit, plus the device as the unit on N-BaIoT. The MDE is (t.975 + t.80)/t.975 × the median CI half-width of the FedProx/FedAdam/FedLC comparisons, a reasonable approximation. With n = 5, the minimum two-sided Wilcoxon p is 0.0625, so "cannot reach p < 0.05" is correct.
- **N-BaIoT preparation** (prepare_nbaiot.py): a Bernoulli 3% sample per device–class file (seed 42); deduplication at float32; rows with conflicting labels dropped; classes with fewer than 100 distinct records dropped (BASHLITE tcp/udp); a 70/15/15 split stratified by device × class; zero-variance features dropped; min–max scaling fitted on training; a cross-split guard. This matches S1A, with the nuance in M8.
- **TON/UNSW pipeline.** `pipe.transform` is called without SMOTE (SMOTE applies only when fitting), and the split is 70/15/15 stratified with seed 42.

### Code bugs that could change results
None found. Things checked specifically and found correct:
- the SCAFFOLD step count K, including the drop-last path;
- that `best_w` and earliest-max selection agree;
- that the Adam reset also resets the iteration counter;
- the FedAdam mask for non-trainable weights;
- that the DP accountant's step count equals the steps executed;
- the Poisson sampler is true Bernoulli per record;
- the noise scale is σC;
- that FedLC counts come from the client's own partition;
- that the local-only and federated partitions are identical per repetition (same prng seed and call sequence);
- the pairing of own-traffic sites (same client order);
- the Holm step-down monotonicity;
- that the personalisation runs re-train with the same seeds, so differences come only from GPU non-determinism (disclosed, up to 0.109);
- that compute_values overwrites the round-2 `tuned.json` values with tuned_v3.json before use.
